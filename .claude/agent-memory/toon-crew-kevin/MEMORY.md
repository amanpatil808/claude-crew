- A plugin cannot ship the main statusLine (plugin settings apply only `agent` and `subagentStatusLine`, and the subagent status line has no rate_limits). For plan windows use a mod's `session.measure` / `$.session.usage().rateLimits` (CC >= 2.1.287). (seen 2) [crew]
- A mod has no documented way to find CLAUDE_PLUGIN_DATA, and hook payloads carry no rate limits. To get mod data to disk, have the mod `$.env.set` one literal variable, which reaches every process started later, and have an async settings hook (which does get CLAUDE_PLUGIN_DATA) copy it through an allow-list. Why: plan-usage 2026-10-28; rateLimits is "empty off a subscription", so empty plus cost > 0 means per-token billing. (seen 1) [crew]
- `claude plugin validate <dir>` prints a mod's hooks, calls, and env reads and writes. Use it as a free, offline proof of a mod's surface, next to a test that gives the mod a Proxy `$` which throws on any call outside the allow-list. (seen 1) [crew]
- On Node 26, `node --test <dir>` treats the folder as one module (MODULE_NOT_FOUND) and the default reporter prints `ℹ fail N` even when piped. Run the CI glob form, and pass `--test-reporter=tap` to any script that parses `# fail N`. (seen 1) [crew]
- Guard path rules for a worktree-isolated role are relative to its own checkout (the git checkout holding cwd, if inside the project), not CLAUDE_PROJECT_DIR: either may be the worktree. Test with project dir = main checkout, = worktree, and the plain checkout. (seen 1) [project]
- Old-code proofs for a guard role test must run outside the system temp dir: read-only roles may write anywhere under temp, so "cannot" cases pass there for the wrong reason. Put the `git archive` copy in a gitignored `.work-*` folder in the worktree, and delete it with a node script (the guard refuses `rm -r` outside temp). (seen 2) [project]

Any new allowance in the data folder must be decided before that rule runs. Test two layouts: one under a fake `.claude/plugins/data`, and a custom folder where builders were never limited. (seen 1) [project]

Check each part with lstat, and test with dangling file and folder links. (seen 1) [crew]
- Claude Code's Write tool creates missing parent folders at umask modes (0755 folders, 0644 files). An owner-only rule has to come from a 0700 ancestor made beforehand, plus a periodic re-tighten. (seen 1) [crew]

- Never name a board event field with token, session, secret, password, cookie or similar words: `redactDeep` (plugin/board/lib/redact.ts SENSITIVE_PROP) replaces the whole value with "[redacted]", numbers included. Why: proved on 2026-10-27, where `inputTokens` and `cacheReadTokens` were wiped by `appendEvent`. Use short neutral keys (`in`, `out`, `cr`). (seen 2) [project]
- Keep counts out of event `text`: `redact()` masks a 10-digit run starting 6-9 as [phone] and a 13-19 digit Luhn-valid run as [card]. Why: big token counts are plausible. Put numbers in numeric fields only. (seen 2) [project]
- Claude Code transcripts write one API response as several adjacent lines that repeat the same `message.usage`. Dedupe on `message.id` (keep the last id seen) before summing, or totals come out about 2x high. Main and `subagents/agent-<id>.jsonl` files don't overlap (verified on CLI 2.1.310). (seen 2) [crew]
- The toon-crew guard refuses heredocs, `node -e` with import(), Bash lines with grep patterns that contain `\(` or `function`, and sed with a `$VAR` path in a worktree-isolated agent. Worktree isolation also refuses git mixed into compound commands. Write scratch scripts with the Write tool, run them in a separate Bash call, and run git as a plain `git -C <worktree>` call. (seen 3) [project]
- Before proposing that the guard log anything, remember it is sync with onFailure: block and fails closed, and its proof tests run the real script. Any new I/O there can turn an ask into a deny or write to the live ~/.toon-crew. Prefer an async hook.ts branch on Notification/PermissionRequest. (seen 1) [project]
- Build token-shaped test fixtures by concatenation ("sk-ant-" + "..."); `.gitleaks.toml` allow-lists only named test files and gitleaks scans every commit. (seen 2) [project]
- Layered guards (lstat before open, inode re-check after open) hide each other in mutation tests; give the inner layer its own test (swap the file between check and open). On Linux, swap by rename, never rm-then-write: ext4 reuses the inode. For an outer symlink filter backed by a realpath-in-root check, test it with a link that points inside the root, which realpath cannot catch. A chmod after `writeFileSync({mode})` hides the create mode the same way: test chmod with a looser temp file planted first. A `continue` before a lookup that drops unknown keys anyway is an equivalent mutant, so mutate it into something observable instead. A layer that only narrows a race you can't trigger without an injection point (such as a per-file re-check after a per-folder one) gets no test, so drop it and report the race. (seen 5) [crew]

- Never compute a time window from cumulative snapshots by subtraction. Bucket at the source by each record's own timestamp, and sum the newest snapshot's buckets for the window's days. Why: a long session first seen today put its whole lifetime in "Today" (P0, 2026-10-28). Old rows without buckets count toward all-time only. (seen 1) [crew]

- Raising a poller's list limit (gh pr list -L 10 -> 20) makes older items look new to a seen-set that is already seeded. Store the window size in seen.json and record the newly visible items silently once. (seen 1) [crew]
- To prove a set of fixes, use a mutation runner in the scratchpad: for each fix, replace the line, run that fix's test file, expect fail > 0, then restore the file. This is faster and safer than a second worktree or a stash. Pair it with a run of the new tests on a `git archive` of the old code (export shims only). A rule that only adds an allowance (such as "unset env allows nothing new") can't fail on old code, so pair the refusal with the same call allowed when the env is set, and kill the realistic bug (guessing the value) by mutation. (seen 3) [crew]
